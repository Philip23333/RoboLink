# 第四步：指令状态跟踪与 WebSocket 双向桥接

状态：已实现并验收（2026-10-20）。对应总路线第 4 个实现单元，未创建 Git 提交。新增 29 项测试，总计 83 项 Java 测试与 36 次三端消息比较全部通过。

## 目标

控制客户端通过 WebSocket 向指定机器人提交有限动作，网关转成 TCP 消息，接收设备 ACK 与执行结果，再回传给原控制会话。支持设备快照、遥测订阅和上下线通知，为后续 Vue 控制台提供真实接口。

## 已实现范围

- 控制端使用独立账号、凭证及设备权限集合，不复用机器人凭证。
- 校验 Origin 和固定 `/control` 路径，不允许查询参数携带凭证。
- WebSocket 首条二进制消息认证；握手和认证均有期限。
- 一个完整 Binary Message 对应一个 Envelope，处理 WebSocket 分片聚合，不附 TCP 长度头。
- 订阅允许访问的设备，返回在线 / 离线快照，推送最新遥测及上下线状态。
- 指令权限、参数、设备在线状态、忙碌状态与已有非空闲遥测检查。
- 按具体设备会话路由，分别跟踪本地发送、ACK、结果、拒绝和超时。
- 重复请求在保留窗口内返回已有状态，不重新发送；不同参数或不同控制会话复用 ID 被拒绝。
- 设备断线、会话替换或控制端断开后，未完成指令结束为 UNKNOWN，不自动重试。
- ACK / 结果超时后不把迟到消息改成成功；已发送的未知指令阻止新运动，仍允许 STOP。
- 未完成指令、短期记录、控制连接、协调队列和每个控制端的输出队列有上限。
- 遥测积压按设备保留最新值，指令结果不静默丢弃；队列超限或持续不可写时断开控制连接。

## 验收入口


## 关键约定

- ACK 默认 2 秒，从指令准入开始计时，包含本地调度；结果默认 5 秒，从接受 ACK 开始计时。
- 同一设备最多一条运动和一条 STOP 等待处理，STOP 可中断运动，具体中断由设备报告。
- 同一个 command_id 的原请求按设备 ID 和参数比较；结果只属于发起请求的 WebSocket 会话。
- 短期状态保留默认 60 秒，未完成与保留记录合计最多 1024 条；满额拒绝新请求，不提前逐出未过期记录。
- 过期或网关重启后不承诺去重；后续模拟器仍须按 command_id 做本地执行去重。
- 超时是执行结果不确定，不表示设备已停止。STOP 成功确认或设备建立新会话后可解除对应不确定状态；不自动重放运动。
