## 真实网关联调

测试启动真正的 Java 主程序，TCP 和 WebSocket 绑定本机随机端口，使用临时随机凭证。三台设备目标遥测频率均为 10 Hz，自动化控制客户端按正式顺序握手、认证和订阅。

| 场景 | 观测和断言 |
| --- | --- |
| 三台设备上线 | 快照包含三台在线设备，均持续发送遥测 |
| RB-001 前进 | 0.2 m/s × 400 ms = 0.08 m；分别收到 ACKED、SUCCEEDED 和空闲遥测；其他设备位置未改变 |
| RB-002 转向 | 先左转 0.2 rad，再右转 0.1 rad，最终 yaw=0.1 rad |
| 重复控制请求 | 同一控制会话重发相同请求，返回已完成状态，设备没有再次移动 |
| RB-003 STOP | 运动期间 STOP，原指令 INTERRUPTED，STOP SUCCEEDED，后续位置保持不动 |
| 参数限制 | 0.6 m/s 的前进被网关拒绝；设备独立参数验证由模型测试覆盖 |
| 正式启动入口 | 另外启动 `python -m robolink_sim`，默认三设备成功注册，完成一条真实控制指令 |

首轮记录中，直接客户端阶段三台设备分别发送 15、16、16 条遥测；测试控制端分别接收 14、15、15 条实时遥测。快照与实时消息统计口径不同，控制端开始订阅的时间也晚于设备启动，不能据此认定消息丢失率。命令状态变化会触发额外状态上报，目标 10 Hz 也不等于严格恒定输出。

Python 测试与集成验证合计约 4.4 秒，其中真实网关联调约 2.9 秒，均不含前置 Java 构建和 Java 测试耗时。这是短时功能验证，没有测量持续吞吐、P99 延迟、CPU / 内存峰值或最大连接数。

## 未验证与限制

没有 Vue 页面，没有自动重连、网关重启恢复、真实网络丢包、实体硬件、持久化或并发性能结论。本次没有修改共享协议或 Java 源码，没有重跑三端 36 次互解；该项历史结果仍见第四步记录。

动作和电量是平面软件模型；本地停止受故障检测和事件循环调度时间影响。短期去重不跨进程，记录满时拒绝新请求；满额 STOP 仍停止本地动作，但以 CAPACITY 拒绝该 STOP 的准入，不伪造已保存的成功状态。自动重连及故障隔离在第六步实现。
