# 第一步：工程骨架与共享协议

状态：已实现并验收（2026-10-19）。实际结果见 `docs/acceptance.md`，修改说明见 `docs/changes/001-工程骨架与共享协议.md`。尚未创建 Git 提交。

## 目标

让 Java 网关、Python 模拟器和 TypeScript 控制台能够使用同一份 Protobuf 协议，并通过固定样例验证三端消息互通。这是后续 TCP 网关和控制闭环的基础。

## 执行顺序

1. 检查本机 Java、Python、Node、Maven 及协议生成工具，记录实际版本；缺少工具时再安装或采用可复现的项目内工具。
2. 建立 `protocol/`、`gateway/`、`simulator/`、`console/`、`scripts/` 和文档结构，配置忽略规则、Java 21 构建骨架及各语言所需的最小依赖。
3. 定义第一版 `.proto`：公共 Envelope、设备注册与回应、心跳、遥测、指令请求、ACK 和结果，以及后续控制台订阅与状态消息。记录字段单位、会话与序号语义、版本规则。
4. 固定生成工具和运行时版本，提供 Java、Python、TypeScript 的协议生成入口；统一生成文件位置和入库策略。
5. 选用包含设备 ID、序号、时间戳及位姿的固定样例，执行三种语言之间的编码与解码，验证字段值一致，特别检查 64 位整数和 `oneof`。
6. 补充 README 中的环境、生成及验证步骤，并按模板记录本次修改说明。

## 本次技术栈应重点理解什么

| 技术 | 本次应用 | 修改说明中的解释重点 |
| --- | --- | --- |
| Protobuf | 用一份消息定义生成三端消息类型和二进制编解码能力 | 统一协议如何减少字段不一致；字段编号、版本、`oneof`、64 位整数如何约定 |
| Java 21 + Maven Wrapper | 建立网关构建入口，管理依赖与 Java 协议生成 | 如何固定构建方式，使后续 Netty 网关能重复构建 |
| Netty | 确定网关依赖和后续职责边界 | 后续负责 TCP 连接、分帧、事件处理；本提交是否实际调用必须如实说明 |
| Python | 建立模拟器协议依赖及验证入口 | 如何编码和解码同一套消息；asyncio 通信将在后续提交实现 |
| TypeScript | 建立控制台协议依赖及验证入口 | 如何获得消息类型和二进制编解码能力，避免手写消息结构 |

Vue 页面、设备 TCP 服务、心跳调度和实际运动分别在后续步骤实现。本次三端互通指序列化互通，网络通信由第二步开始验证。
