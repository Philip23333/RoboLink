# 修改说明：断线重连与故障恢复

日期：2026-10-20。实现提交：`e870f5b`。

## 场景一：RB-001 掉线，其他机器人继续工作

RB-001 前进时连接断开，Python 先停止它的本地运动，再单独尝试重连。RB-002 不需要跟着退出。asyncio 为每台设备安排独立恢复循环；指数退避逐渐拉长重试间隔，随机抖动避免所有设备同时冲向刚恢复的网关。

重新注册得到新会话编号，消息序号重新开始，位置保持断线停止时的位置。旧发送队列被清理，旧运动不会自动恢复；设备进程内尚未过期的去重记录仍然保留。

## 场景二：机器人执行了动作，网页却一直没收到结果

可以指定一台设备故意不回第一条指令的 ACK，或不回执行结果。前者检查网关是否提示 ACK 超时，后者检查结果超时；超时只说明云端无法确认，不能解释为设备没移动。机器人仍靠本地计时停止，STOP 可单独发起。

ACK 延迟通过限额队列安排稍后发送，不让程序原地等待，因此心跳和运动计算仍可继续。这是应用层故障模拟，不是真实网络丢包。
