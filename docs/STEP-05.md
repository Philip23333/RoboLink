# 第五步：多机器人模拟器与有界动作

状态：已实现并验收（2026-10-20）。对应路线第 5 个执行单元，未创建 Git 提交。

## 目标与交付

把“测试设备按脚本回包”推进为“设备持续运行，接收命令并计算自己的新位置”。默认启动 RB-001、RB-002、RB-003，分别保存位置、朝向、电量和运动状态，以 10 Hz 为目标频率发送遥测。

已实现：

- Python asyncio TCP 连接、长度帧读取、Protobuf 注册、会话与序号校验。
- 心跳按网关返回的间隔发送，只有匹配的心跳回复能解除等待。
- 每连接一个发送任务统一分配序号，串行发送完整帧；关键回复最多排队 64 条，遥测仅保留最新一条。
- 前进、左转、右转、STOP；设备再次校验动作、有限数值、速度和 1–3000 ms 时长。
- 接受后 ACK，实际经过时间驱动运动，结束后 Result；STOP 中断原动作并分别报告原动作与 STOP 的结果。
- 每台设备最多一个运动；重复 command_id 重放已有 ACK / Result，不重做运动；同 ID 不同参数拒绝。
- 断连、取消、心跳响应超时或发送失败后本地停止，不等待云端补发 STOP。
- 用户启动入口、24 项 Python 测试，以及真实 Java / WebSocket / 三设备和命令行启动联调。

## 启动与验证

完成 README 的环境准备与协议生成后，先启动带控制端口的网关，在另一个终端执行：

```powershell
.\scripts\start-simulator.ps1 -CredentialFile .\gateway\devices.local.properties
```

可配置 `-Count`、`-IdPrefix`、`-TelemetryHz`、`-GatewayHost`、`-Port`。设备 ID 从前缀加三位起始编号生成；所有选中的 ID 必须已配置凭证。数量范围 1–1000 只是输入限制，本次仅验证三台，不构成并发能力声明。遥测频率范围为大于 0 且不超过 100 Hz；受操作系统调度影响，不是精确实时周期。

本次统一验收：

```powershell
.\scripts\verify-simulator.ps1
```

它构建网关并回归全部 Java 测试，再验证 Python 模型、本机 TCP 行为和真实 WebSocket 控制闭环，报告输出到 `artifacts/simulator/report.json`。

## 行为约定与边界

- 前进默认演示参数 0.2 m/s，最大 0.5 m/s；转向角速度最大 1 rad/s，逆时针为正。这些是软件模拟限制，不是实体机器人安全参数。
- 运动积分截断在动作截止时刻；周期调度迟到不会多走。运动更新和心跳检查独立于遥测上报频率。
- 初始位置为 (0,0)、(2,1)、(4,2) 米，朝向为 0；初始电量为 87%、86%、85%。运动期间按演示消耗模型扣电，不模拟真实动力学和电池特性。
- 每台设备最多保留 256 条指令记录，终态或拒绝后保留 60 秒；执行中记录不过期。容量满拒绝新指令，不提前逐出记录；STOP 即使满额也本地停下，但返回 CAPACITY 拒绝，不承诺未保存指令的成功和去重。
- 去重记录只在模拟器内存和保留窗口内有效，进程重启或记录过期后不提供执行一次保证。
- 凭证读取支持简单 UTF-8 的 `ID=token` 行、空行和注释，不支持 Java Properties 的转义及续行；建议使用 README 的随机十六进制凭证。
- 本阶段连接只尝试一次。命令行运行时任一设备失败会结束整个模拟组并停止本地动作，自动重连和设备间故障隔离留给第六步。
- 当前只有自动化控制客户端，没有网页；本次未验证网关重启恢复、真实网络丢包、实体机器人或并发上限。
