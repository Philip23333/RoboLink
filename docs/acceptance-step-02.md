## 分帧验证结果

| 类别 | 实际验证方式与结果 |
| --- | --- |
| 基本收发 | 完整消息可解析；编码结果与独立构造的 4 字节大端帧一致 |
| 半包 | 遍历样例所有两段切分点，另逐字节送入；完整前不产生消息 |
| 连续多帧 | 一次送入三条完整消息，按顺序还原 |
| 完整帧加残帧 | 第一条立即交付，第二条等剩余字节后交付 |
| 随机拆分 | 20 个固定种子，每次 100 条状态、分段长度 1–300 字节，全部顺序与字段一致 |
| 连接隔离 | 一个连接残缺的长度头不会影响另一个连接 |
| 大小边界 | 65536 字节消息体可收发，帧总长 65540；65537 字节声明立即拒绝 |
| 极大长度 | 0x80000000 与 0xffffffff 不被当作合法小长度或负数绕过限制 |
| 异常消息 | 零长度、损坏的 Protobuf、错误版本、缺少 payload 均关闭连接 |
| 异常后的数据 | 同批输入中坏消息后的正常消息不会交付业务层 |
| 断线残帧 | 长度头或消息体未完整时关闭，无业务消息，残留缓冲引用计数归零 |
| 出站检查 | 超限、缺内容或原始字节对象被拒绝，不输出该消息；原始字节缓冲被释放 |
| 真实本机 TCP | Java Socket 发送三条消息，Netty 测试服务逐条原样回复，长度与字段一致 |
| 真实异常连接 | 只发送超长长度头，客户端观测到 EOF，不需要补消息体 |

JUnit 汇总：**23 项测试，失败 0、错误 0、跳过 0**。其中内存测试 21 项、真实本机 TCP 测试 2 项。随机拆分的 2000 条消息比较包含在一个测试方法中，不另计为 2000 个独立测试，也不作为吞吐量成绩。

真实网络可能重新合并多次写入，因此“准确指定拆分点”的证据来自内存测试；本机 TCP 测试用于证明真实连接的收发与关闭行为。
